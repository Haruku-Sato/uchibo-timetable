# 段階8：前後の便と「所要時間が短い順」

## 1. 前後の便を見られるようにする（検索画面）
- 結果の一覧の**上**に「◀ 前の便」、**下**に「次の便 ▶」のボタンを置く。
  押すたびに、今の一覧より前（または後）の経路を3件ずつ足す。
  - 出発時刻指定：前の便は、指定時刻より前に出る経路。
  - 到着時刻指定：次の便は、指定時刻より後に着く経路。
- 指定した時刻の範囲の外から足した経路は、カードを少し淡くし、「指定時刻より前に出発」「指定時刻より後に到着」のラベルを付ける。指定の範囲の外だと分かるようにする。
- 時刻や駅を変えたら、足した分はリセットする。
- 前後にもう経路がないとき（始発より前、最終より後）は、ボタンを無効にして「これより前（後）の便はありません」と表示する。
- **路線図の結果パネル**：「内訳を見る」の中に「1本前の便：20:05発 → 21:19着」（最終より早く着く経路のうち一番遅く出るもの）を1行出す。最終を逃しそうなときの目安になる。

## 2. 並び順：「出発順」と「所要時間順」
- 検索画面の、出発／到着の切り替えの近くに「並び：出発順｜所要時間順」の切り替えを足す。選んだ並びは localStorage に保存する。
- **所要時間順**の動き
  - 対象の範囲：出発時刻指定なら「指定時刻〜指定時刻＋N時間」に出発する経路、到着時刻指定なら「指定時刻−N時間〜指定時刻」に到着する経路。
    N は「2・3・4・6時間・終日」から選ぶ。初期値は3時間。終日は始発〜最終。
  - 範囲内の経路（遅く出て早く着く経路があるものを除いた集合。今の journeys と同じ考え方）を、**所要時間（出発〜到着）の短い順**に並べる。
    所要時間が同じなら、早く着くほうを先にする。
  - 先頭のカードには「この条件で最短」のチップを付ける。一覧の上に1行、「○時〜○時の出発で一番早いのは 16:39発（1時間18分）」のように書く。
  - 6件を表示し、残りは「さらに表示」で出す。
- 各カードには、所要時間に加えて**乗車時間**（列車とバスに乗っている時間の合計）と**待ち時間**（乗換の待ちの合計）を小さく出す。
  例：「所要1時間18分（乗車1時間8分・待ち10分）」
- 「この区間の最終」を表示している間は、並びの切り替えを隠す。

## 3. ロジック（src/search.mjs）
- `journeysRange(net, o, d, {mode, from, to}, opts)`：範囲内の経路を、遅く出て早く着く経路があるものを除いて返す（並べ替えはしない）。
  今の `journeys()` はこれを使って書き直してよい。
- `rideTime(j)`、`waitTime(j)` を追加する。
- 前後の便は、範囲を前後に広げて `journeysRange` を呼び、今の一覧にない経路から近い順に3件取る。

## テスト（バス25分・乗換余裕2分・平日）
- 君津→千葉、所要時間順・終日：1位は**16:39発（17:57着、78分）**、2位は**8:07発（9:26着、79分）**。
- 君津→千葉、出発時刻指定 8:00：先頭は8:07発。「前の便」で7:44発が加わり、「次の便」で9:03発が加わる。
- 君津→千葉、到着時刻指定 9:42：先頭（最終）は8:07発。「次の便」を押すと、9:42より後に着く9:03発（10:39着）が淡い表示で加わる。
- 千葉→君津の路線図パネル：1本前の便は **20:05発（君津21:19頃着）**。
  「1本前」は、最終より早く着く経路のうち一番遅く出るもの。千葉20:15発は最終と同じ21:58着になるので、1本前には数えない。
- `rideTime` と `waitTime` の和が、所要時間に等しい。
- 既存のテストと、PWA 版（site/）のテストがすべて通る。
